# 12단계 설계와 실행 계획

기준 커밋: `b53eb6412c3ed666892ddefc79b7ff81bab1fc50` (11단계 세션 자동 승인).
README 단계와 HEAD는 일치한다. 예전 허용 경로·Production 로그인 안내는 갱신한다.

현재 기능: Supabase 로그인 프록시, 서버 소유권 검사 메모 CRUD, 계약 판정기와 탐지기,
단건 메모·정책 복구, manifest와 session_id별 서버 승인이다.

## 설계

- 기존 자료실에 별도 작전실 탭을 추가한다. 승인된 세션만 열 수 있고 메모 본문은 표시하지 않는다.
- Hobby 함수 개수를 늘리지 않도록 기존 session-approval catch-all에 읽기 전용 operations 경로를 추가한다.
- 서버가 만든 UUID 요청 ID·UTC 확인 시각·경로 템플릿·HTTP 상태·검사 커밋만 감사 테이블에 저장한다.
  사용자 UUID는 소유자 필터에만 사용한다. 토큰, session_id, 이메일, 쿼리, 제목, 본문은 기록·응답하지 않는다.
- 최근 본인 서버 기록 최대 100건과 동일한 배열에서 허용·거부·오류 수치를 계산한다.
  기록 실패는 응답 헤더에 명시하고 기존 자료 API 결과를 성공으로 바꾸지 않는다.
- 규칙 목록은 실제 RULE_IDS, 복구 기준은 기존 정책 사본, 메모 버전은 본인 백업 메타데이터에서 읽는다.
  백업 존재와 실제 복구 성공은 구분한다. 운영 엔진의 판정·탐지 사건·회수 결과는 연결되어 있지 않으므로 미실행이다.
- 1~11단계 정상·금지 요청 계획과 실제 HTTP 결과·요청 ID·시각을 한 표로 제공한다.
  자동 검사는 읽기와 인증 없이 거부되어야 하는 요청만 보낸다. 승인·변경·삭제·복구는 자동 실행하지 않는다.
  엔진·교차 계정·복구 검사는 조건이 없으면 미실행이다. 이는 공식 총공세 시험 목록이 아니다.
- 공식 41종 이름·결과 계약이 저장소에 없으므로 총수 41, 실행 0, 미실행 41로 표시하며 통과 수는 미확인이다.
- 학생 코드와 제공 ALEPH SDP 엔진의 출처, 설치·실행·중지·복구 순서와 검사 커밋 확인 방법을 README에 적는다.

## 실행 순서

1. 의미 있는 보안 테스트부터 작성: 본인 기록만 반환, 본문·키 차단, 승인 없는 접근 거부,
   실측 결과만 성공 처리, 미실행/통신 실패 구분, 상태와 서버 기록 수치 일치.
2. 메타데이터 감사 테이블 추가 및 서버 기록 훅·operations API 구현. 기존 동적 route 코드를 보존.
3. 표 생성 모듈과 작전실 UI 구현. 메모 자료실과 탭을 나누고 로그아웃 때 작전실 기록도 지운다.
4. 재현용 CLI 점검, 실제 DB schema/RLS 확인, Stage 1~11 회귀·계약·깨끗한 설치 확인.
5. README와 step=12 갱신, 비밀값·diff 검사, `12단계 저장점` 커밋, main 푸시와 Production 확인.
6. 커밋·배포 SHA를 대조하고 bundle을 생성한다. 실제 실행하지 못한 항목은 최종 보고에도 미실행으로 남긴다.

Production 자료 변경 시험은 실행하지 않는다. 실제 엔진/41종 결과를 추정하거나 웹 승인 DB를 deviceRegistered로 연결하지 않는다.
